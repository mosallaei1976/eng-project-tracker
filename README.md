معرفی پروژه
nezam-crm-pwa یک وب‌اپلیکیشن تک‌فایلی و کاملاً آفلاین برای ثبت و مدیریت پروژه‌های نظام مهندسی است. این پروژه با HTML/CSS/JavaScript خالص (بدون هیچ وابستگی خارجی) نوشته شده و به‌صورت PWA (Progressive Web App) منتشر می‌شود؛ یعنی با یک بار باز شدن در مرورگر، روی گوشی یا کامپیوتر نصب می‌شود و پس از آن حتی بدون اینترنت هم کامل اجرا می‌شود.
مخاطب اصلی این ابزار اعضای سازمان نظام مهندسی هستند که نیاز دارند فهرست پروژه‌های طراحی و نظارت، تخصص‌ها، مشخصات پروژه‌ها و یادداشت‌های کاری خود را در یک محل امن و شخصی نگه دارند — بدون ارسال هیچ داده‌ای به سرور.
معماری: تک‌فایلی (index.html با CSS و JS تعبیه‌شده) + sw.js
ذخیره‌سازی: محلی و سمت کاربر (localStorage)
میزبانی: GitHub Pages (رایگان و HTTPS)
ویژگی‌های کلیدی
✅ مدیریت پروژه‌ها: ثبت، ویرایش و حذف پروژه‌های طراحی و نظارت با دو نمای «فهرست» و «جزئیات»
✅ مدیریت ۸ تخصص مهندسی: دسته‌بندی پروژه‌ها بر اساس رشته (عمران، معماری، تاسیسات برقی و مکانیکی، شهرسازی، نقشه‌برداری، ترافیک و مهندسی ارزش)
✅ یادداشت‌ها: ثبت یادداشت‌های کاری متصل به هر پروژه
✅ پشتیبان‌گیری و بازیابی: خروجی گرفتن از تمام داده‌ها در قالب فایل JSON و بازگردانی آن در هر دستگاه دیگری
✅ نصب به‌عنوان اپلیکیشن: تولید پویا.Manifest و قابلیت Add to Home Screen روی اندروید، iOS و دسکتاپ
✅ کارکرد صددرصد آفلاین: کش شدن کامل رابط کاربری با Service Worker
✅ طراحی واکنش‌گرا و موبایل‌محور: رابط کاربری فارسی و راست‌به‌چپ بهینه برای گوشی
✅ بدون وابستگی (Zero-dependency): بدون npm، فریم‌ورک یا بیلد — کافی است دو فایل را منتشر کنید
معماری و نحوه ذخیره‌سازی داده
تمام داده‌های کاربر (پروژه‌ها، یادداشت‌ها و تنظیمات) در localStorage همان مرورگر و همان دستگاه ذخیره می‌شود. این یعنی:
هیچ داده‌ای به گیت‌هاب یا هر سرور دیگری ارسال نمی‌شود.
هر دستگاه دیتای مستقل خودش را دارد؛ پروژه‌ای که روی گوشی ثبت می‌شود، روی لپ‌تاپ دیده نمی‌شود مگر با خروجی/ورودی JSON منتقل شود.
پاک کردن داده‌های مرورگر یا حذف اپلیکیشن، داده‌ها را از بین می‌برد — بنابراین گرفتن پشتیبان منظم JSON به‌شدت توصیه می‌شود.
Service Worker و کش آفلاین
فایل sw.js در ریشه مخزن، هسته قابلیت آفلاین است. طبق مستندات MDN، یک Service Worker مانند یک پروکسی بین صفحه و شبکه عمل می‌کند و با رویدادهای install و activate منابع برنامه را در Cache ذخیره و در رویداد fetch پاس‌ها را از کش ارائه می‌دهد (Using Service Workers — MDN). سرویس‌ورکرهای فعلی فقط در بستر امن (HTTPS یا localhost) کار می‌کنند که GitHub Pages این شرط را به‌صورت پیش‌فرض برآورده می‌کند.
در این پروژه:
در install، فایل‌های ./ و ./index.html در کش با نام crm-cache-v1 ذخیره می‌شوند.
در activate، کش‌های نسخه‌های قدیمی با caches.delete پاک‌سازی می‌شوند.
در fetch، پاس ابتدا از کش و در غیر این صورت از شبکه ارائه می‌شود (استراتژی Cache-first).
نکته برای توسعه: هر بار که محتوای index.html را تغییر دادید، مقدار CACHE_NAME را در sw.js به مثلاً crm-cache-v2 افزایش دهید تا کاربران نسخه جدید را دریافت کنند.
localStorage برخلاف کش سرویس‌ورکر همگام (synchronous) است و در سرویس‌ورکر در دسترس نیست؛ به همین دلیل داده‌ها و کش فایل‌ها دو لایه جدا هستند.
استقرار روی GitHub Pages
این پروژه روی GitHub Pages بدون هیچ فرآیند بیلد منتشر می‌شود:
مخزنی با نام nezam-crm-pwa بسازید (Public، بدون تمپلیت، بدون .gitignore).
دو فایل index.html و sw.js را در ریشه مخزن قرار دهید و مستقیماً روی شاخه main کامیت کنید.
از منوی Settings → Pages، بخش Source را روی Deploy from a branch و شاخه را روی main / (root) تنظیم کنید.
پس از چند ثانیه، آدرس https://<username>.github.io/nezam-crm-pwa/ فعال می‌شود.
صفحه را در گوشی باز کنید و گزینه Add to Home Screen / نصب برنامه را بزنید؛ از این پس برنامه آفلاین هم اجرا می‌شود.
برای توسعه محلی، کافی است index.html را با یک سرور ثابت باز کنید (مثلاً python -m http.server یا افزونه Live Server) تا ثبت سرویس‌ورکر روی localhost نیز کار کند. باز کردن مستقیم فایل با پروتکل file:// باعث می‌شود Service Worker و منیفست غیرفعال بمانند.
راهنمای استفاده و پشتیبان‌گیری
خروجی پشتیبان (Export)
از دکمه خروجی JSON در برنامه استفاده کنید؛ یک فایل شامل تمام پروژه‌ها، تخصص‌ها و یادداشت‌ها دانلود می‌شود. توصیه می‌شود این فایل را به‌صورت دوره‌ای در محل امنی (ایمیل شخصی، ابر شخصی یا حافظه دستگاه) نگه دارید.
بازیابی (Import)
در دستگاه مقصد، از دکمه ورودی JSON همان فایل پشتیبان را انتخاب کنید تا داده‌ها بازگردانی شوند. این مکانیزم تنها روش انتقال داده بین گوشی و کامپیوتر است، چون داده‌ها محلی ذخیره می‌شوند و همگام‌سازی ابری وجود ندارد.
نکات ایمنی داده
قبل از پاک کردن کش مرورگر یا تعویض گوشی، حتماً خروجی JSON بگیرید.
حالت ناشناس (Incognito) داده‌ها را پس از بستن مرورگر حذف می‌کند؛ از آن برای کار روزمره استفاده نکنید.
